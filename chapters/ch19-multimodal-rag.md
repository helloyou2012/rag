## 第 19 章　Multimodal RAG（多模态 RAG）

> **一句话概括**：在文本、图片、图表和表格之间进行检索。

### 19.1 要解决的问题

真实世界的企业知识大量存在于**非纯文本**载体中：

- 扫描版 PDF、PPT、合同影印件；
- 财报里的**图表、趋势图**；
- 产品手册里的**示意图、爆炸图、界面截图**；
- 大量的**表格**（财务报表、参数表）；
- 音频与视频（会议录音、培训视频）。

传统做法是"先把一切转成文字"（OCR、PDF 文本提取），但会遭遇：

- **版面信息丢失**：多栏、页眉页脚、阅读顺序错乱；
- **表格结构被破坏**：行列对应关系丢失，数字失去含义；
- **图表信息完全丢失**：趋势、对比、图例只能靠肉眼读取；
- **图片内容无从检索**："找到那张显示电路连接方式的图"。

### 19.2 工作原理

对应图中流程：`PDFs, Images, Tables → Vision Encoder → Multimodal Index → Vision LLM`

**三种主流架构**

| 方案 | 做法 | 检索对象 | 生成 | 优缺点 |
|---|---|---|---|---|
| **A. 全部转文本（Text-ification）** | 用 OCR/版面分析/表格识别提取文本；用视觉模型为图片、图表**生成文字描述**；统一当作文本 RAG | 文本（含图像描述） | 文本 LLM | 简单、复用现有链路；描述质量决定上限，细节易丢 |
| **B. 多模态嵌入（Joint Embedding）** | 用 CLIP/SigLIP 类图文联合嵌入模型，把图片与文本映射到**同一向量空间**；文字查询可直接检索图片 | 文本块 + 图像 | 多模态 LLM（Vision LLM） | 可直接"以文搜图"；对精细文本/图表理解有限 |
| **C. 文档页面图像检索（Page-as-Image）** | 把每一页**直接当作图像**，用视觉文档检索模型（如 ColPali 一类，基于视觉语言模型 + 延迟交互/多向量）嵌入；查询为文本，匹配页面图像 | 页面截图 | 多模态 LLM 读取命中的页面图像 | 免 OCR/版面解析，保留布局、图表、表格；**索引存储更大、算力更高** |

**典型端到端流程（以 B/C 为例）**

1. **解析**：把 PDF/PPT 拆成页面；可选地做版面分析（标题、段落、图、表）。
2. **视觉编码**：用视觉编码器（Vision Encoder）将图片/页面转为向量。
3. **多模态索引**：存储向量，并保存原始图像/文本、页码、来源等元数据。
4. **检索**：文本查询编码 → 检索相关图/页/文本块（也可以用图片作为查询）。
5. **生成**：把检索到的**文本 + 图片**一起交给**视觉语言模型（Vision LLM）**，由其综合理解并回答。

**各类内容的处理要点**

| 内容类型 | 推荐处理 |
|---|---|
| **表格** | 提取为 Markdown/HTML/CSV 结构并**保留表头**；同时生成一段"表格摘要"用于检索，原表用于生成；大表按行块/列块拆分并带上表头 |
| **图表** | 视觉模型生成"图表描述 + 关键数据点 + 趋势结论"；或直接送图给 Vision LLM |
| **示意图/截图** | 图像描述 + OCR 文字 + 周边说明文字；或联合嵌入 |
| **扫描文档** | OCR（注意质量与版面） 或页面图像检索 |
| **音视频** | 语音转写（ASR）+ 时间戳切分；视频可再抽关键帧并描述 |

### 19.3 实现要点与代码

**方案 A + 表格/图表增强：生成式描述（多模态"文本化"）**

```python
import base64

def describe_image(image_bytes: bytes, kind: str = "chart") -> str:
    """使用 Vision LLM 为图像生成可检索的文字描述。"""
    prompt = {
        "chart": "详细描述这张图表：图表类型、坐标轴含义、各系列、关键数据点、整体趋势与结论。",
        "diagram": "描述这张示意图：包含的组件、它们之间的连接/流程与图中的文字标注。",
        "table": "把这张表格还原为 Markdown 表格，保留表头与所有数值，不要遗漏。",
    }[kind]
    return vision_llm(image=base64.b64encode(image_bytes).decode(), prompt=prompt)

def index_page_elements(elements, store: VectorStore):
    """elements: 版面解析得到的 [{'type': 'text|table|figure', 'content': ..., 'page': n, 'image': bytes?}]"""
    ids, texts, metas = [], [], []
    for i, el in enumerate(elements):
        if el["type"] == "text":
            text, raw = el["content"], el["content"]
        elif el["type"] == "table":
            md = el["content"]                                   # 已解析为 Markdown 的表格
            summary = llm(f"用 2-3 句话概括这张表格的内容与关键数值：\n{md}")
            text, raw = f"{summary}\n{md}", md
        else:  # figure
            desc = describe_image(el["image"], kind="chart")
            text, raw = desc, desc
        ids.append(f"p{el['page']}-{i}"); texts.append(text)
        metas.append({"type": el["type"], "page": el["page"], "raw": raw,
                      "image_ref": f"img/{el['page']}-{i}.png" if el["type"] == "figure" else None})
    store.add(ids=ids, vectors=embed(texts), texts=texts, metadatas=metas)
```

**方案 B/C 的检索与生成（示意）**

```python
def multimodal_answer(question, mm_index, k=4):
    q_vec = mm_embed_text(question)                       # 多模态嵌入模型的文本编码器
    hits = mm_index.search(q_vec, k=k)                    # 命中：文本块 / 图像 / 页面截图
    parts = [{"type": "text", "text": f"问题：{question}\n请仅依据下列资料作答，并标注来源页码。"}]
    for h in hits:
        if h["metadata"]["type"] in ("figure", "page_image"):
            parts.append({"type": "image", "image": load_image(h["metadata"]["image_ref"])})
        parts.append({"type": "text", "text": f"[来源: {h['metadata']['source']} p.{h['metadata']['page']}] {h['text']}"})
    return vision_llm_chat(parts)
```

**选型建议**

| 场景 | 建议 |
|---|---|
| 文本为主，偶有图表 | A：文本化 + 表格/图表描述，成本低、易调试 |
| 图片检索是核心需求（以文搜图/以图搜图） | B：联合嵌入 |
| 版面复杂、图表/表格密集的 PDF（财报、论文、幻灯片） | C：页面图像检索（可与 A 并用：A 负责召回，C 负责补充视觉信息） |
| 成本敏感、规模巨大 | 先 A，再对"高价值页面/文档"启用 C |

### 19.4 优点与代价

**优点**

- **覆盖完整知识**：图表、表格、示意图中的信息不再被忽略。
- **保留版面与视觉线索**（尤其页面图像方案），减少解析错误。
- 能回答**视觉类问题**："第 12 页的趋势图说明了什么？"
- 与 Vision LLM 结合，可做**跨模态推理**（图 + 文字）。

**代价**

- **索引与存储成本高**：图像向量（特别是多向量方案）体积大；生成描述需要大量 Vision LLM 调用。
- **生成成本高**：图片进入上下文消耗大量 token。
- **工程复杂度**：解析器、版面分析、多种嵌入模型、图像存储与引用。
- **精度风险**：Vision LLM 读数字可能出错（尤其是密集表格、小字号图表）。
- 多模态嵌入对**细粒度文本匹配**不一定优于纯文本嵌入。

### 19.5 适用场景

- 财报、研报、科研论文、技术手册、PPT 库。
- 工业/医疗/设计领域，图像本身是主要知识载体。
- 电商/媒资：以图搜图、图文混合检索。

### 19.6 常见陷阱

1. **只解析文字**：忽视表格与图表，导致"文档里有，但永远搜不到"。
2. **表格被拆散**：表头与数据行分家，数字失去语义。分块时务必**保留表头**。
3. **只存图像描述，不存原图/原表**：生成阶段无法核对细节；应**保留原始素材引用**。
4. **全部走图像**：图像 token 昂贵；先用文本召回，再对少量命中页使用图像。
5. **图像分辨率不当**：过低看不清，过高成本爆炸。
6. **没有引用定位**：多模态回答同样需要给出**页码/图号**以便核对。
7. **数字不核对**：对关键数值应交叉验证（如表格原文与 Vision LLM 读数是否一致）。

### 19.7 与其他技术的组合

- **+ 元数据过滤（11）**：按页码、文档类型、模态（text/table/figure）过滤。
- **+ 混合检索 + 重排序（3、4）**：文本召回 + 多模态重排序。
- **+ 父子分块（10）**：以"图/表说明"为子块，回溯到所在章节为父块。
- **+ 路由（9）**：根据问题是否涉及"图/表/趋势"决定是否启用视觉检索。

### 19.8 本章小结

多模态 RAG 的核心思想是：**别让信息因为"不是文字"而无法被检索与理解。** 实践中从"文本化 + 表格/图表描述"起步，再对高价值内容引入页面图像检索，是性价比最高的路径。

## 19.9 案例与实战

> 说明：案例为虚构示例，数字仅作示意。

### 案例：研报里的图表与表格

**背景**：卖方研报 PDF，关键结论藏在图表和表格里，如“近五年毛利率趋势图”“分业务收入表”。

**症状**：文本提取只得到图注，用户问“2022 年哪个业务毛利率最高”无法回答。

**方案（分层）**
1. 版面分析，拆出文本、表格、图；
2. 表格 → Markdown（保留表头）+ 一段摘要；图 → Vision LLM 生成“描述 + 关键数据点”；
3. 召回走文本化索引；命中后，对**少量关键页**同时把页面图像交给 Vision LLM 复核数字；
4. 回答必须给出页码与图号。

**结果（示意）**：图表/表格类问题正确率 0.31 → 0.77；Vision 复核仅对 Top-2 页启用，把成本控制在可接受范围。

### 实战 19：表格与图表的文本化索引

**步骤**
1. 选 3–5 份含图表/表格的 PDF，用版面分析工具（如 PyMuPDF、pdfplumber 或同类工具）提取表格与图片。
2. 对表格：转 Markdown、保留表头、生成摘要；对图表：用 Vision LLM 生成描述（图类型、坐标轴、关键数据点、结论）。
3. 构造 20 个必须依赖表格/图表才能回答的问题（含数字）。
4. 比较：仅文本提取 / 加表格处理 / 再加图表描述 / 再加页面图像复核，记录正确率与成本。
5. 做“数字核对”：随机抽 20 个数字，核对原表与 Vision 读数，统计错误率。
