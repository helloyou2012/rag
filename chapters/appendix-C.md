## 附录 C　RAG 故障排查手册

### C.1 分层排查法

遇到一个"答错了"的案例，按下面的顺序**逐层**检查，不要一上来就改提示词：

| 步骤 | 检查 | 方法 |
|---|---|---|
| ① 数据 | 答案所需信息**是否在知识库里**？解析是否正确？ | 直接在原文里搜；检查解析后的文本（表格、多栏、OCR） |
| ② 分块 | 答案是否被**切断**？块是否缺背景？ | 查看相关块的原文与边界 |
| ③ 召回 | 正确块是否在 **Top-50** 里？ | 打印召回列表及分数；分别检查向量路和关键词路 |
| ④ 排序 | 正确块排在第几？是否在 **Top-k** 内？ | 对比重排序前后名次 |
| ⑤ 上下文 | 正确块是否**真的进入了提示词**？是否被截断、被噪声淹没？ | 打印最终提示词 |
| ⑥ 生成 | 上下文里有答案，模型是否**没用好或编造**？ | 检查提示词、温度、模型；做忠实度评估 |
| ⑦ 输出 | 格式、引用、拒答是否合规？ | 检查后处理 |

### C.2 常见症状速查

| 症状 | 可能原因 | 对策 |
|---|---|---|
| 搜编号/型号/错误码找不到 | 纯向量检索 | 混合检索；检查分词 |
| 同义说法就搜不到 | 嵌入模型弱、语料术语不一致 | 换/微调嵌入模型；多查询；HyDE；同义词扩展 |
| 第一轮对，第二轮就错 | 没做指代消解 | 查询改写（对话历史） |
| 命中了但答案只说一半 | 块太小 | 父子分块；扩大窗口 |
| 答案里混入旧版本信息 | 缺少版本过滤 | 元数据过滤；文档去重/版本管理 |
| 回答了不该回答的（越权） | 权限没在检索层强制 | 服务端强制元数据过滤 |
| 总是胡编"听起来对"的内容 | 无拒答指令；检索质量差 | 强化提示词；Corrective RAG；阈值拒答 |
| 回答很长但跑题 | 上下文噪声大 | 重排序；压缩；减少 k |
| 表格数字错误 | 表格解析破坏结构 | 表格专项解析 + 保留表头 + 核对 |
| 对"总结全库"类问题很差 | 向量检索天然局限 | GraphRAG（Global）/ 分层摘要 |
| 延迟忽高忽低 | 重试、Agent 步数不可控 | 步数上限；自适应分流；缓存 |
| 换了嵌入模型后效果骤降 | 忘记**重建索引** | 全量重新嵌入，保持查询与文档同模型 |
| 线上和离线评估不一致 | 评估集不代表真实分布 | 用线上日志更新评估集 |

### C.3 上线前检查清单

- [ ] 评估集（含无答案、多跳、时间约束样本）与基线分数已建立。
- [ ] 文档解析抽检通过（表格、多栏、扫描件）。
- [ ] 查询与文档使用同一嵌入模型/同一预处理。
- [ ] 权限过滤在服务端强制，**不依赖 LLM**。
- [ ] 提示词包含"仅依据资料""资料不足则拒答""引用来源"。
- [ ] 设定了超时、重试、步数与成本上限，具备降级方案。
- [ ] 日志可追溯完整链路（问题→召回→排序→上下文→答案）。
- [ ] 有用户反馈入口，且坏案例能回流到评估集。
- [ ] 对提示词注入（来自文档/网页的恶意指令）有防护。
- [ ] 数据更新、删除（含合规删除）的流程已验证。
