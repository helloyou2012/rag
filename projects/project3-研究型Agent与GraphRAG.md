# 综合实战项目 3：研究型助手（Adaptive 入口 + Agent + GraphRAG）

> 目标：面向研究员/分析师，处理开放式、需要多步探索的问题，并控制成本。
> 涉及章节：8、9、14、15、16、17、18、20。
> 说明：这是进阶项目，建议在完成项目 1 后进行。数字与指标均为建议。

## 一、整体设计

```
用户问题
  │
  ▼
Adaptive 入口（none / single / multi，带升级机制）
  ├─ none   → 直接回答
  ├─ single → 固定流水线：改写 → 混合检索 → 重排序 → 生成（轻量支持度检查）
  └─ multi  → Agent 循环（最大步数/预算上限）
               工具： search_docs | graph_local | graph_global | sql_readonly | web_trusted | calc
               反思： 证据是否足够？不足则改写/换工具；重复调用检测
               输出： 带引用的报告 + 不确定性说明
```

## 二、分步实施

### 步骤 1：固定流水线先行
复用项目 1 的检索栈作为 `search_docs` 工具，确保 single 路径质量达标。

### 步骤 2：GraphRAG 作为专用工具（第 14 章）
- 先在 50–100 份文档上验证抽取质量与收益，再扩大范围；
- 提供两个工具：`graph_local(entity)`（实体+邻居+相关块）与 `graph_global(question)`（社区报告 map-reduce）；
- 每个实体/关系保留来源块 id，输出中可溯源。

### 步骤 3：Agent 循环与护栏（第 15 章）
- 最大步数（如 8）、最大 token、重复调用检测；
- 工具权限最小化：SQL 只读 + 白名单；Web 限定可信域名；
- 外部内容视为数据，不得改变系统指令（提示词注入防护）；
- 全链路 Trace（每步思考/工具/参数/观察/耗时/成本）。

### 步骤 4：Adaptive 入口与升级（第 18 章）
- 分类器（规则 / 嵌入 + 逻辑回归 / LLM 少样本）；
- 关注“欠检索率”（multi 被判 single）；single 低置信度时升级到 multi。

### 步骤 5：质量闸门（第 16、17 章）
- Agent 最终答案前做论断级核验；证据不足则明确说明，不强答。

### 步骤 6：评估（第 20 章）
- 评估集：单步 / 多步 / 全局总结 / 关系 / 无答案 / 工具失败；
- 指标：答案质量、证据覆盖、步数、成本、失败恢复率、护栏触发次数。

## 三、验收标准（建议）
- [ ] 复杂任务完成率显著高于固定流水线，同时平均成本低于“全部走 Agent”。
- [ ] 所有任务都有可读 Trace；步数/预算上限被真实触发过并优雅降级。
- [ ] 提示词注入与越权工具调用测试通过。
- [ ] 全局类与关系类问题上，GraphRAG 的收益有数据支撑；简单事实类没有退化。

## 四、成本控制技巧
- 小模型做分类与评分，大模型做规划与最终合成；
- 对文档前缀使用提示词缓存；
- 观察结果截断（如 ≤ 4000 字符）；
- 对重复问题做结果缓存（注意权限维度）。
