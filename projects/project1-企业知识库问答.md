# 综合实战项目 1：企业知识库问答（从 0 到 1 的四周计划）

> 目标：为一家 200–2000 人的公司，做出可上线的内部制度/IT/产品文档问答系统。
> 涉及章节：1、2、3、4、5、10、11、12、20（可选 13、16）。
> 说明：下面的周计划、指标目标均为**建议值**，请按你的数据调整。

## 一、需求与约束

| 项 | 内容 |
|---|---|
| 用户 | 全体员工，多轮对话，移动端与网页 |
| 数据 | Word/PDF/Wiki，约 1000 篇，含多版本制度 |
| 硬约束 | 权限隔离（部门/岗位）、答案带引用、不知道就说不知道 |
| 非功能 | P95 < 6s；单次成本可控；可观测 |

## 二、目标架构

```
离线： 解析清洗 → 结构化分块(+标题路径前缀) → 子块/父块 → 元数据(部门/版本/权限/日期)
        → 向量索引 + BM25 索引
在线： 改写(条件触发) → 权限+业务过滤 → 混合检索(RRF) → 重排序 Top-5
        → 父块展开(应用同样过滤) → (可选)压缩 → 生成(带引用) → (可选)支持度检查
监控： 全链路日志 + 评估集回归 + 用户反馈
```

## 三、四周计划与验收

### 第 1 周：基线 + 评估（第 1、20 章）
- 文档解析与清洗：抽检 30 个文档的解析结果（表格、页眉页脚、多栏）。
- 固定大小分块 + 向量检索 + 拒答提示词，跑通端到端。
- **建评估集**：≥ 60 条（真实问题 + 专家编写），分类别：单跳/编号/时间版本/权限/无答案。
- 验收：有基线指标；有失败样本表；评估脚本可一键运行（可基于 `labs/lab01_mini_rag.py` 与 `labs/eval_set_template.jsonl`）。

### 第 2 周：检索质量（第 2、3、4、10 章）
- 改为按标题层级的结构化分块，必要时对长段落做语义分块。
- 加 BM25（注意中文分词与型号/编号保护）+ RRF；再加重排序。
- 父子分块：子块检索，父块（≤ 1500 token）生成，并实现去重。
- 验收：每项改动都有“前后对比表”（分类别）；若某项没有收益，**不上线**。

### 第 3 周：元数据、权限、查询理解（第 5、11、12 章）
- 元数据 schema：`tenant/dept/acl_groups/doc_version/effective_date/title_path`。
- 权限过滤由后端强制注入；编写 ≥ 10 条越权探测测试。
- 多轮改写（条件触发）；先做“标题路径前缀”，评估后再决定是否上 LLM 生成上下文（第 12 章）。
- 验收：越权测试 100% 通过；多轮对话命中率显著提升；版本类问题不再混用旧版本。

### 第 4 周：上线准备（第 13、16、20 章）
- 低置信度回退：重排序分数低于阈值 → 明确拒答 + 转人工入口；记录判定。
- 评估回归接入 CI；日志字段齐全；设超时/降级（重排序超时 → 跳过）。
- 灰度：先 10% 流量 + 👍/👎；每周审查坏案例并回流评估集。
- 验收：评估报告（见第 20 章模板）；上线检查清单（附录 C.3）全部勾选。

## 四、关键设计检查清单

- [ ] 权限过滤不经过 LLM，且父块展开时同样生效（实验 1 已演示该陷阱）。
- [ ] 文档更新/删除时，向量库、BM25 索引、父块存储**同步**更新。
- [ ] 生成时使用原始块；引用含文档名、章节、页码。
- [ ] 评估集分层，保留独立测试集。

## 五、可选扩展
- 引入第 16 章：库外问题的 Web 回退（限定域名）。
- 引入第 17 章：对高风险主题（薪酬、合规）开启支持度检查。
- 引入第 18 章：问候/通用问题走“不检索”。

## 六、常见失败与应对

| 现象 | 可能原因 | 对策 |
|---|---|---|
| 引用了已废止制度 | 缺版本/有效期过滤 | `effective_date` + `doc_version` 过滤，旧版归档 |
| 编号搜不到 | BM25 分词吞掉编号 | 编号/型号整词保护 |
| 答案不完整 | 块太小 | 父子分块 |
| 回答越权内容 | 权限过滤缺失或展开父块时丢失 | 后端强制 + 测试用例 |
