# 综合实战项目 2：财报 / 合同分析助手（高精度型）

> 目标：面向分析师与法务，回答带精确引用、数字可核对的问题。
> 涉及章节：2、3、4、8、9、10、12、13、16、17、19、20。
> 说明：流程为建议方案，指标均需用自己的评估集验证。

## 一、需求特点
- **精度第一**：宁可拒答，不可编造；每个数字、条款必须能回溯到页码。
- 文档特点：代词多（“该公司”“本季度”）、表格密集、条款有“例外/但书”。
- 问题特点：对比（跨年度/跨公司）、多跳、计算类。

## 二、架构

```
离线：版面分析 → 文本/表格/图分流
      文本：按条款/章节结构分块 → 父子块 → 上下文检索(公司/期间/章节)
      表格：Markdown(保留表头) + 摘要；图：Vision 描述 + 关键数据点
      元数据：公司/期间/文档类型/页码/章节路径
在线：路由(文档 | 结构化指标库 | 计算器)
      → 复合问题分解(并行/串行)
      → 每个子问题：混合检索 + 元数据过滤(公司、期间) + 重排序
      → 父块展开 + 抽取式压缩(保留原文句，保留“但是/除非”邻句)
      → 评分闸门(Corrective)：证据不足 → 明确拒答
      → 生成(逐条引用) → 论断级支持度核验(Self-RAG 式)
      → 数字复核：对关键数字与原表交叉验证
```

## 三、实施步骤与验收

1. **文档解析质量门**：随机抽 50 个表格/50 张图，人工核对解析正确率，目标先达到你设定的下限再进入下一步。
2. **索引**：实现 `index_page_elements`（第 19 章），表格带表头切分；为文本块加“公司/期间/章节”上下文前缀（先标题路径方案，评估后再用 LLM 生成上下文）。
3. **检索**：混合检索 + 元数据过滤（公司、期间必须作为硬过滤）+ 重排序；父块展开遵守同一过滤条件。
4. **问题处理**：
   - 对比类 → 并行分解（每个公司/年度一个子问题）；
   - 多跳 → 串行分解，限制 ≤ 4 步；
   - 计算类 → 交给计算工具，LLM 不心算。
5. **质量闸门**：检索评分低 → 拒答；生成后做论断级核验，不被支持的论断删除或标注。
6. **评估**：专家标注 ≥ 100 题，类别：单跳事实 / 表格数字 / 图表趋势 / 对比 / 多跳 / 计算 / 无答案；指标：正确率、引用准确率、数字错误率、拒答正确率。

## 四、验收标准（建议）
- [ ] 数字类问题全部附页码，抽查 50 个数字，错误率达到你设定的上限。
- [ ] 无答案问题的拒答正确率明显高于误拒率。
- [ ] 对比类问题的证据覆盖率（每个比较对象都有证据）。
- [ ] 全链路日志可复现任意一个回答。

## 五、风险与对策
| 风险 | 对策 |
|---|---|
| Vision 读错数字 | 关键数值与原表交叉验证；图表仅作辅助证据 |
| 压缩丢掉例外条款 | 转折词邻句保护；法务场景优先“不压缩，只重排序” |
| 子问题错误传播 | 串行链路逐步校验证据；证据不足即停止并说明 |
| 期间/公司混淆 | 公司、期间作为硬过滤；回答中回显所用过滤条件 |
